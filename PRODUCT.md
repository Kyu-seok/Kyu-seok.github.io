## Platform

web

## Stack

Vite + React + TypeScript, plain CSS with custom-property tokens (user chose Vite + React + TS; CSS approach delegated). Static build deployed to GitHub Pages at https://kyu-seok.github.io/ via a GitHub Actions workflow. Free-text questions are answered by a self-hosted Qwen3 model behind a small Go gateway (`server/`) on the CodeBite mini PC at ask.code-bite.com; the page works fully without it (see docs/adr/0001).

## Users

Recruiters, hiring managers, and fellow engineers who land on kyu-seok.github.io from a résumé, LinkedIn, or a GitHub profile. They are deciding in under a minute whether Kyu-seok is worth a conversation. Korean and English readers both; language is a toggle and the chat answers in the active language.

## Product Purpose

A single-page portfolio for 염규석 (Kyu-seok Yeum), a backend engineer in Seoul. It replaces a dormant Jekyll blog. Success: a visitor learns who Kyu is, sees CodeBite and kyu-rios as real, running work, and reaches GitHub, LinkedIn, or email without hunting.

## Positioning

The portfolio is a conversation, modeled on the "ask me anything" chat portfolio format (reference: aaabadcode.com, a Fastfolio site). Unlike that reference, the chip answers are authored by Kyu and served statically, and free-typed questions are answered live by a Qwen3 model running on the same Intel N100 that grades CodeBite submissions. The model only speaks from a fact sheet Kyu wrote, every generated reply is labeled as generated, and the page falls back to scripted replies whenever the model is slow or down.

## Operating Context

- Visitors arrive on phones and laptops, in daylight, usually from a link in a résumé or a LinkedIn post.
- kyu-rios lives at https://kyu-seok.github.io/kyu-rious/ in its own repo (Kyu-seok/kyu-rious, Pages via workflow). This site must not interfere with that path.
- The repo previously deployed a Jekyll build to the `gh-pages` branch. Pages must be switched to "GitHub Actions" as its source for the new site.

## Capabilities and Constraints

- Five quick actions: Me, Projects, Skills, Fun, Contact. Each opens a chat answer with a rich card.
- Free-text input in either language: the keyword matcher picks the intent and card instantly; the prose is generated by the model (streamed, single-turn, thinking off) if its first token arrives within the time budget, otherwise the scripted reply renders. Chips are scripted. Korean questions are capped at 40 characters (about one token per character on this CPU) and get a reply saying so when longer. Korean generation shipped on 2026-11-08 by decision although the second spike missed the quality bar (server/spike/RESULTS.md, docs/adr/0001); the question log decides whether it stays.
- Small talk (greetings, jokes, boredom, questions about the chat) is answered by the model in a voice section Kyu wrote; out-of-scope questions are declined by the model. Both go through the same prompt; the matcher still owns intent and card. The model has no tools, so the harms guarded against are reputational and CPU on the production box, not system damage. Shipped 2026-11-08 by decision over a failed small-talk bench (`server/spike/RESULTS.md`, docs/adr/0001); reviewed against the question log by 2026-11-22 or after 50 unknown-intent questions, revert if the replies are a problem.
- Generated replies carry a stamp: model name, tokens per second, total time, and a link to a "how does this chat work?" scripted reply.
- The gateway holds the fact sheet, caps input/output/concurrency, rate-limits per IP, and keeps a permanent question log (disclosed on the page).
- Language toggle KO/EN; initial language from the browser, remembered in localStorage.
- No analytics, no cookies, no external scripts on the page. The only network call is to ask.code-bite.com, made on the visitor's first interaction, never on page load.
- Avatar: the user's own memoji with transparent background at `public/avatar.png`, shown inside a peach circle.
- Fun = kyu-rios second brain only (user decision). Book reviews from the old blog are not included.

## Product Principles

1. Every factual claim on the page is something Kyu actually did or believes; no filler claims. Generated prose may be playful, in a voice Kyu wrote, and is always labeled as generated.
2. Generated replies are grounded in Kyu's authored fact sheet and are always labeled as generated. The model may make small talk in Kyu's voice but adds no facts; the fact sheet states explicitly what is not disclosed and what is out of scope (code, translation, general knowledge, opinions on people or politics) so the model declines instead of inventing.
3. Projects are shown running (screenshots, live links), not described abstractly.
4. Both languages are first-class; neither reads as a translation afterthought.
5. The page stays fully usable as a static site when the model is unreachable, and CodeBite always wins the CPU over the chat.
